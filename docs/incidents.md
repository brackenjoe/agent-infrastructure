# Incidents, and the rules they produced

[Back to the README](../README.md). Most rules in this setup exist because
something went wrong first. These are twenty-nine that produced a rule and
two that have not yet, from nine weeks of running it (September to early
November 2026), newest first. Security details are left out; the rule each
one produced is in the live files, and where the guide carries it, the
row links there.

| Date | What went wrong | How it was caught | Rule now |
|---|---|---|---|
| 2026-11-05 | A web app's deploy printed "all checks passed" every time while a block of 12 network-backed self-checks was skipped. On the server the self-test ran as the service account from a directory it could not write; the cache error was caught and printed as a skip, and the deploy counted only failures. | Seen in a later deploy's output | Only a real network failure skips; any other error is a counted failure; the deploy prints each skip, or `skips: none`. | 2026-11-04 | The enforcement table said the agent-file ask rule held in every mode. Under bypassPermissions on 2.1.318, a Bash `sed -i` and a heredoc both rewrote an agent file. | 2026-11-04 | The ask rule meant to prompt on `--no-verify` matched that spelling only. git 2.43.0 accepts any unambiguous abbreviation, and `git push --no-verif` skipped the pre-push hook with no prompt: a refusing hook returned 1 plainly and 0 with the abbreviation. `git -c core.hooksPath=/dev/null`, and `gh` commands that write a repository without a push, had no rule either. | A read-only review of the agent server's drift since its last review; the manager reran the bypass in scratch repositories | Ask rules on `--no-veri` (the shortest form git accepts), on `hooksPath` in either case and on `gh` write forms. An earlier review had read the list of refused words, not how a line was read. | A security audit by agents found it in the tool's source; the parent checked the firmware's source; the firmware's simulator measured it: the setting was saved, and the bootloader reset was reached | A gate judges the line the executor will run, not the line as typed: any byte outside printable ASCII, or a character the editor acts on, is refused, and a restore accepts only the commands a backup contains. Two later corrections: the cold review of the fix found that the comment character cuts a line too (read from the firmware source, refused since), and the allowlist, read from the firmware's source, missed a command a backup carries for some airframes (measured in the simulator; it failed safe, and is allowed since) ([drone-tools](https://github.com/brackenjoe/drone-tools)). |
| 2026-11-02 | The sandbox for an audit's target code could not create its namespaces. The simpler design, `systemd-run --user` on its own, would have run the command anyway without the network and mount isolation, with only a journal line for the network namespace ("proceeding without") and nothing for the rest. | Measuring each control while building it, before any target code ran. ## Four patterns

1. **A claim from reasoning or a single negative, not a measurement:** the
   reachability claim, the predicted audit findings, the watchdog, the
   upgrade theory, the first enforcement table, the firewall that was
   "on", the stale repository description, the allowlist whose comments
   described what its regular expressions did not do, the sandbox design
   that would have dropped its isolation with a note in a journal.
2. **A check that existed but did not exercise the act:** the
   guarded-looking delete, the `active` service, the result read from a
   report, the permission check that could pass without a refusal, the
   secret scan that could pass without scanning, the reboot timer that
   never fired, `visudo -cf` on one file, the command gate that read the typed line
   and not the one the firmware ran, the permission check that probed only
   the file tools, the ask rule that matched one spelling, the deploy that
   counted failures and not skips, the audit landing that ran after a
   failed check.
3. **Cost from routing, not capability:** the most expensive failure was not
   a wrong answer but the right work done by the wrong model.
4. **An instruction, not a permission:** the builder's commit, the briefs
   that told it to commit, a public push stopped by a sentence, and for six
   weeks the whole stop rule, while the agent owned every file it was told
   not to touch. The table of
   [what enforces which rule](../README.md#the-rules-and-what-enforces-them)
   is the short list of rules that are not like this; the user split
   moved the stop rule's paths onto it.

The cheap, bounded builders checked the stronger orchestrator more often
than the reverse, because their file lists made them measure before they
could change anything. The two reviews of the records by fresh sessions
with none of the context found the three security items of 2026-10-23
and 10-24 that six weeks of the setup's own checks had not, and the cold
review of this guide found the fourth.
